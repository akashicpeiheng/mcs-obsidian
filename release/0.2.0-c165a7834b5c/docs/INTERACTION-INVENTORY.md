# 从 MCS 网站继承什么，怎样改进

日期：2026-10-13。REF 表示已读到本仓库源码或规格；FINITE 表示插件已有具体检查。没有把源码阅读写成网站的完整真人可用性评估。

## 最有价值的学习方式

先围绕一个原型问题挑出少量对象，再沿有登记依据的联系增加节点。以“消元为什么不改变答案”为例，先放入域、行操作、矩阵，随后比较计算路线与结构路线。这个过程从熟悉操作长成抽象结构，也能让学习者保留自己的组织方式。

另一条动机来自检验：画出一条边后，学习者可以追问它用了哪些条件、删去条件有什么反例、是否存在另一条路线。生长链是浏览关联 → 自己组图 → 写清联合条件 → 检查精确陈述 → 反过来修改学习背景观察后果。

## 必须改掉的语义问题

0.2.0 同时采用 [Obsidian 原生 Graph 的交互](https://obsidian.md/help/plugins/graph)：吸引、排斥、拖动、悬停聚焦和缩放。独立运动层使用 [d3-force](https://d3js.org/d3-force/simulation)，远景圆点、近景卡片有回差；外观切换不改中心。当前实现仍是 MCS 文件视图，原生 Graph 的私有内部对象不构成运行依赖。

FINITE：插件测试检查以下改动，不因此声称已验证所有认知效果。

- 网站旧回放的 `uses` 是此前全部可见节点，插件只显示真实 `action.inputs`；否则会把旁观对象误说成证明前提。
- 网站旧回放在空入口时把首个产出放进第零帧，插件保留空背景，执行事件后才出现产出。
- 网站旧回放会省略没有新节点的非复习事件，插件保留完整事件与来源。
- 网站的学习布局按硬前置距起点的层数排列；联合条件的路线需要等待所有来源，所以插件采用所选事件依赖的最大前置层次。
- 网站快照未保存布局模式、锚点和内容版本；插件视图显式保存这些字段。迁移旧快照时提示按 ID 匹配的边界。
- 纸笔标签 PROOF、有限检查 FINITE、外部引用 REF 和本机证书通过分开表示；自然语言对应仍要审阅。

## 怎样使用这些交互学习

1. 用一个具体问题冷启动：例如把两条方程相减，为什么答案不变？先记录猜想。
2. 加入刚好够用的背景。域提供可除的主元，行操作提供可逆改写，矩阵把系数组织起来。
3. 对每个条件做删减实验：乘零、只改系数、把域换成非域，分别看结论怎样崩溃。
4. 比较计算和结构两条路线：消元给一个答案，核与特解给全部答案的结构。
5. 在沙盘中删去一个背景。检查是哪一个事件先失败，而不是把整张图都判成不可学。
6. 压缩思想：把试错与证明收束成“简化要带回程”和“相减消去共同部分”，再回看能否迁移到新问题。

NOT-CLAIMED：上述设计尚未证明能改善学习成绩或长期记忆。试用需要记录理解错误、操作时间与学习者解释，再作评价。

思想：图要让学习者看见“为什么”，也保留“我可以怎样想”。方法：原型问题、条件删减、备选路线比较与回看压缩，分别用于上面的六步。
