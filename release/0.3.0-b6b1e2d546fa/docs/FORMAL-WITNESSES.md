# 定义、实例与反例：从理由到核验依据

日期：2026-10-15。版本：0.3.0。DEF 是本页的接口约定；实现的有限验收记录见 `validation/desktop.json` 的 `witness`。检查器自身未经形式化验证，教材对应仍须单独审阅。

## 为什么增加见证

学习时，名字相同不保证定义相同，算过几个例子也不能证明一般命题。研究时，需要固定符号类型、来源版本和检查目标，才能知道改动以后哪份结果失效。两条动机汇成这条生长链：写自然理由 → 固定精确表达 → 选择关系专用依据 → 独立重放 → 比较条件变化。

三份便携案例都带有四条未核验练习。打开“关系工作室”，逐条点击“形式检查”，再展开“核验范围与见证”。它们使用原教材地图的节点作入口，机器表达只覆盖说明中的精确模式；`sourceReviewed` 均为 false，不表示已经逐句编码了这些节点或教材。

## 定义引用：谁引入了这个符号

直觉：输出表达真的用到了输入节点引入的定义，来源可以追回；这不等于输出表达已经成立。

在编辑器选择“定义引用”，填入来源节点与输出节点，开启形式表达。在来源下面写已有背景符号、引入的定义，最后列出输出实际使用的定义符号。示例：来源定义 `Id: V -> V := λx:V. x`，输出局部声明 `a: V`，输出写 `Id a = a`。输入陈述可写 `true`，这里只记录其语法背景，不将它作为命题证明。

DEF：`formalSources` 是当前视图的局部作者登记，按节点 ID 保存 `{version, declarations, definitions:[{name,type,source}]}`。它不修改公共内容 M，也不修改笔记正文。定义体只能使用该来源登记的原始背景符号与其他明确登记的定义，必须是闭项；消费者的局部参数不能偷渡进定义体。每个定义符号有唯一引入节点，声明不能遮蔽它。

检查器核对定义体类型、旧语言闭项、输出 AST 中的实际常量出现、来源与节点版本、符号依赖和节点依赖无环。定义体按依赖排序后由 Python 原有内核重建；引用与无环义务另行重放。已登记定义引用的循环会使当前检查失败，合法等价环不参加这个循环检查。输出使用的全部定义符号都须注明来源，每个输入都须提供实际使用的符号。

通过标签是 **DEF 来源检查**，不产生输出命题的证明。局部背景符号是明确假设的签名，未由本轮判断器验证其数学解释或教材出处。

## 实例：代入与满足是两种义务

直觉：既可以把通用模式代到一个具体项，也可以在给定有限对象上逐项检查一个描述；两者须分开读。

选择“全称模式的精确代入”时，只接受一个输入模式，按最外层全称量词顺序逐行写项。示例：输入 `∀x:V. x = x`，声明 `a: V`，代入 `a`，目标 `a = a`。目标必须与代入结果一致；尚未消去的量词须保留。类型错、额外代入项、隐含自由变量或不同目标都会被拒绝。

实现复用共享类型解析与避免变量捕获的代入，直接生成 `all_e` 与释放模式假设的 `imp_i` 证书，由 Python ND 内核重放。通过的精确目标是“这个模式蕴含这个实例”；模式本身并未因此得到无条件证明。其开放假设、目标及背景摘要仍按原有规则核对。

选择“给定有限对象的满足见证”时，填写载体、常元和完整运算表。全部输入及输出在指定对象上都须为真。通过是 **FINITE**，只说明这个对象，不推断其他对象。

## 反例：假设真而结论假

直觉：指出条件为什么不能删，要保留其余假设，再找使结论崩溃的对象。

案例的默认两元素表含 `a=0, b=1`，`f(0)=f(1)=0`。输入 `f a = f b` 为真，输出 `a = b` 为假，故“相同像就有相同输入”缺少单射条件。把输入改成 `a = b` 会失败，因为这个对象连假设都不满足；把输出改成 `a = a` 也会失败，因为结论没有崩溃。

FINITE：这是给定表达的反模型。它未自动证明该表是某个向量空间、没有补出标量域，也未自动核对教材原句。要讨论域、群或线性性，相关公理必须明确写成输入义务并核验。

## 有限求值范围与可复现入口

一个非空载体，1–8 个不同字符串元素，最多 32 个常量／运算符号。每个声明与表中的解释须一一对应，运算为同一载体上的一元或二元完整闭表。常元必须取载体中的值。`elements` 顺序对应表的行列，不是数字大小。

仅支持一阶项、载体元素等式、真／假、合取、蕴含、该载体上的全称与存在量词。命题载体、高阶量词、函数相等、λ 项与多载体模型在此有限判断器中不支持。形式语言的析取仍不支持。每条公式按节点数和量词深度预估完整枚举，超过 100000 的预算返回未支持；独立 Python 求值还有 500000 次总操作上限。不会靠截取部分枚举来显示通过。

JavaScript 复用 `mcs-web/core/formal/finite.mjs` 求值，另用随包的 `witness.py` 独立求值。Python 重新检查签名、完整性、闭合、量词及真假；两份结果与精确输入摘要必须一致。完整枚举只在所给有限域上成立。检查报告驻留当前窗口，保存和导入不携带可信状态。

```powershell
npm run check
npm run build
npm test
node scripts/witness-check.mjs
```

修改见证或定义来源会使旧报告过期，界面将其明确显示为旧报告。重开与跨库导入后须重新检查。源登记和见证随 `mcs-view/2`、`mcs-bundle/2` 保存；旧视图读入时补空登记；首次保存缺少此字段的旧第二版文件前，也逐字备份到“旧版备份”。0.2.x 不支持这一新增字段，建议用 0.3.0 打开带专用见证的视图。个人状态 E 不回写公共内容，查看、组网和检查也不自动确认掌握。

回看：通过的是引用、条件模式，还是有限满足？哪个删掉的条件使消去失败？把同样的表改成恒等映射后，原来的反模型还成立吗？

思想：证据随精确义务行走。方法：先区分引用、代入和满足，再用删条件与完整表检查直觉，最后用版本及独立重放维护依据。
