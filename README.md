# MCS 数学认知空间 · Obsidian 插件

当前源码版本：0.3.1，Windows 桌面试用版。最近完成整套桌面验收的安装包为 0.3.0，保存在 `release/0.3.0-b6b1e2d546fa/`；0.3.1 的源码构建与核心测试另见 [GitHub 发布记录](docs/GITHUB-PUBLISH.md)。独立 MCS 视图增加吸引、排斥、弹性拖动、局部聚焦、圆点／卡片切换及分阶段学习回放，继续承载可编辑的形式关系、证据检查和学习沙盘。整个任务按 P0–P6 推进，实际状态见下表。

主题在 0.2.1 跟随 Obsidian 明暗模式：浅色用站点的淡紫纸面、白色面板与深靛正文，深色用深靛背景、紫灰面板与浅紫强调色；令牌集中在 `src/theme.css`，作用域只到工作区与插件设置页。画布上的 SVG、二维 Canvas 回退与 WebGL 图层共用同一套令牌（含中性线与失败色），切换主题时整份刷新。署名与站点同源：作者 **沛恒**，联系邮箱 **peihengmath@gmail.com**（工作面板底部常驻，设置页另有完整署名）。

## 先试一次完整过程

1. 将安装包中的 `mcs-cognitive-space` 文件夹放进库的 `.obsidian/plugins/`，在 Obsidian 的社区插件页面启用。已有同名插件请先保留旧副本。
2. 命令面板执行 **MCS 数学认知空间：新建数学网络**，点击“从消元为何有效开始”，或导入 `examples/calculation.mcspack.json`。
3. 从左侧搜索、筛选与推荐中加入对象。自由布局中拖动会牵动邻居，松手后弹性回稳；用“固定位置”或 Shift 拖动固定。远景显示圆点，放大或聚焦展开卡片；逻辑核心与学习顺序平滑移动后静止。
4. 在“关系工作室”选择联合输入、输出、关系类型，先写条件和解释，再编辑形式表达并检查。
5. 在“学习沙盘”选择计算路线或结构路线。勾选沙盘的域背景，观察前提 → 联合关系 → 结论依次突出；坐标在播放中保持稳定。删去背景，观察实际失败的输入来源。模拟不写入真实掌握记录。
6. 保存、关闭再打开，或导出便携包到另一库。便携包携带内容快照和视图；真实学习记录独立保存在插件数据中。

全书地图示例是 `examples/book-map.mcspack.json`；结构路线是 `examples/structure.mcspack.json`。导入网站导出的单个快照、快照数组或 `{views:[...]}` 时，可以在预览中选取视图；未匹配的节点会明确阻止迁移。

笔记菜单提供“在 MCS 中展开”，命令面板也有同名入口。已有绑定或 `mcs-node-id` 定位对象；未绑定笔记由学习者在选择器中指定对象。动态操作、快捷键与演示见 [动态视图说明](docs/DYNAMIC-VIEW.md)。

## 为什么单独做关系视图

从学习动机看，学习者需要围绕一个具体问题挑出刚好够用的对象，并知道每个条件为何出现。从研究工程看，关系需要固定背景、节点版本、精确目标和可重放依据，修改后才能发现证据失效。生长链是打开笔记 → 自己组图 → 写出联合条件 → 检查形式表达 → 用不同背景演绎路线。

网站已有的好交互、采用方式与改进理由见 [交互与学习方法清单](docs/INTERACTION-INVENTORY.md)。关系、视图、路径及 M/E/D 的边界见 [语义约定](docs/SEMANTICS.md)。

## 形式检查的真实范围

一般关系编辑器目前支持三种 ND 子集检查：条件推导、等价的两个方向、放缩的指定特殊到一般方向。声明有类型的符号，逐行对应输入陈述，并填写结论。搜索在独立进程中运行，候选证书交由单独的 Python 检查器重放；同时核对目标、背景摘要与开放假设。没有找到证明保持未决。

逻辑模式例子：声明 `P: o`、`Q: o`，输入 `P` 和 `P -> Q`，输出 `Q`。这只证明这一逻辑模式；把 P、Q 命名成教材标题并不能证明它们已经准确表达教材内容。对应审阅另有勾选项。

0.3.0 为定义引用接入符号来源、类型与循环检查，为实例接入精确全称代入与有限满足见证，为反例接入“全部假设真、结论假”的独立有限反模型重放。编辑器提供相应字段，三份案例各含四条待核验练习。完整范围和限制见 [专用见证说明](docs/FORMAL-WITNESSES.md)。类比和话题关联也能登记，不自动成为推导或必修前置。

“核验三个示范目标”使用固定 Lean 源文件，依次编译、读取实际环境核对目标与公理、运行独立 `leanchecker`。目标分别是：可逆线性映射消去、特解加核、有限维秩—零度。报告列出 `propext / Classical.choice / Quot.sound` 中实际使用的公理。抽象可逆变换目标尚未覆盖三类具体初等矩阵的构造。

ND 检查需要 Node.js 22+ 与 Python 3，在插件设置可填完整可执行文件路径。组网、笔记、保存和沙盘无需这些解释器，也无需运行 MCS 网站服务。Lean 是可选依赖：固定为 Lean 4.34.1，mathlib 为 `d13f23b723b8a846827a245b89c10fc7d3f11612`；填写原生工具链的 `bin` 目录和已有编译缓存的项目目录。插件核验过程只读取依赖缓存，不自动联网安装工具链。

纸笔 PROOF、引用 REF、有限测试 FINITE、本机检查通过和教材对应审阅分别表达。ND 检查器自身尚未形式化验证，报告不声称完整 HOL 判定能力。

## 教材案例

继承当前网站的 51 个条目（八章、七个组织阶段的地图），新增 6 个示范对象和 2 个外部背景接口，共 59 个节点。网站多数条目是地图入口；已为完整示范链的 10 个对象编写正文、动机、条件反例、证明说明、联动与回看问题。其余条目明确保留正文待完成状态。

已修订两处容易误导学习者的概述：一般域上存在自由参数不必有无穷多解；复内积不能同时在两侧复线性。示范正文为独立重述，全书与形式目标的逐条教材校勘仍待完成。详见 [来源与校勘清单](docs/SOURCE-AUDIT.md)。

## 文件、复用与恢复

- `MCS-workspace/内容/<SHA-256>.json`：不可变内容快照，读入与导入都复核内容哈希。
- `MCS-workspace/视图/*.mcsview`：`mcs-view/2`，保存节点集合、关系草稿、笔记绑定、坐标、锁、布局参数、相机、动态设置、局部定义来源与专用见证、精确事件路线；速度不入文件。
- `MCS-workspace/旧版备份/*.mcsview`：首次保存第一版视图或缺少定义来源字段的旧第二版视图前，逐字保存旧文件，按内容摘要命名；旧副本不参加视图库选择。
- `MCS-workspace/笔记/*.md`：新建的完整 Obsidian Markdown；同名时另取文件名。也可绑定已有笔记。
- `.obsidian/plugins/mcs-cognitive-space/data.json`：解释器设置和按节点 ID、版本记录的个人掌握状态。

移出视图不删除笔记。笔记改名时更新绑定与打开的视图。编辑普通 Markdown 不自动修改公共内容快照；正式修订内容需要新节点版本和新快照。导入创建独立视图 ID，并保留现有文件。多个窗口保存同一视图发生冲突时，原文件和当前编辑的恢复副本同时保留。

本机有效的关系检查报告驻留当前窗口；重新打开或跨库导入后需要再次核验。这防止导入 JSON 自称“通过”就成为有效证据。

便携包使用 `mcs-bundle/2`，同时接受第一版包与网站快照。旧版迁移补齐动态设置，保留坐标、固定点、关系与路线。保存、导出和关闭先停止运动并提交当前画面；重开恢复保存位置，等待下一次交互再运行模拟。`release/` 中的 0.1.0、0.2.0 与 0.2.1 成品继续保留。

顶栏字标（`assets/wordmark.png`，站点现用一笔彩虹字标）与空白引导区／设置页的紫色徽记（`assets/emblem.png`）随插件本地打包，按原比例缩放，断网可用；来源与导出记录见 `design/mcs-logo-v13` 与 `design/mcs-logo-v6`。

## 开发与复现

源码构建复用 `upstream/` 中的 MCS 共享模块快照，单独克隆本仓库即可构建。来源提交与逐文件 SHA-256 见 `upstream/SOURCES.json`；快照中的代码与原创理论分别沿用 MIT 与 CC BY 4.0。更新共享模块时，在主工作区重新导出。

```powershell
git clone https://github.com/akashicpeiheng/mcs-obsidian.git
cd mcs-obsidian
npm ci
npm run check
npm run build
npm test
node scripts/make-examples.mjs
node scripts/witness-check.mjs
node scripts/check-lean.mjs
```
本仓库已有工具链时，Lean 脚本默认使用 `.lean-tools/lean-4.34.1-windows/bin` 和 `.lean-tools/prepared-project`；也可通过 `MCS_LEAN_BIN`、`MCS_LEAN_PROJECT` 指定。成功审计保存在 `proofs/report.json`，最近一次运行状态在 `runtime/lean-last-run.json`；失败不会覆盖上次成功审计。比较源文件哈希后再引用旧报告。

实际桌面测试使用独立配置和测试库，见 `scripts/start-test-vault.mjs` 与 `scripts/browser-check.mjs`。检查记录及边界见 [验收记录](docs/VALIDATION.md)。

主题、品牌与无障碍另有单独一支验收：`node scripts/theme-check.mjs` 会在浅色、深色与窄窗下核对字标与徽记确实加载且保持原比例、署名与邮箱链接正确、普通文字实测对比度 ≥ 4.5:1、工具栏／署名／阅读面板／播放控件互不重叠、切换主题后画布配色整份刷新（并临时关掉 WebGL 复核二维回退用的是同一套令牌）、键盘焦点用主色描边、减少动态效果生效，并断言打包后的每条选择器与每个令牌都限定在插件作用域内。发布版本只在 `manifest.json` 里写一次，`scripts/manifest.mjs` 供各验收脚本读取，脚本里不再写死版本号。

安装到本机库用 `node scripts/install-into-vault.mjs [--vault=...]`：先整目录备份，只覆盖程序文件，安装后逐文件回读哈希，并比对 `data.json` 与整个 `MCS-workspace` 的前后摘要，确保个人掌握记录、笔记、视图与库设置都没动。加 `--dry-run` 只看计划不写入。

性能与稳定性另有独立实例：`node scripts/start-perf-vault.mjs` 起一套专用库、配置和调试端口（`runtime/perf-session.json`），与桌面回归互不干扰。

```powershell
node scripts/host-baseline.mjs --session=runtime/perf-session.json   # 环境地板：空转/空视图/静止/拖动/拖动+缩放
node scripts/perf-check.mjs  --session=runtime/perf-session.json     # 两条绘制路径 × 五个规模 × 重复取样
node scripts/soak-check.mjs  --session=runtime/perf-session.json     # 反复开关视图 + 持续操作
node scripts/compat-check.mjs                                        # minAppVersion 静态核对（不需要实例）
```

三条各自的边界写在脚本头部：`perf-check` 只认两条事先写明的门槛，其余规模如实列出；`soak-check` 卡的是工作集增长与 p95 随时间退化；`compat-check` 是**静态**结论，不能替代在 1.7.2 宿主上的实机运行。判定用的帧延迟取宿主 `requestAnimationFrame` 间隔的第 95 百分位——图收敛后绘制层按需重绘，重绘间隔量到的是输入节奏而不是帧耗时，`perf-check` 会把两者分开记录，只在确实逐帧重绘时才合并。

思想：每一条可操作关系，都应允许学习者读懂理由并复核精确义务。方法：以原型问题冷启动，以条件删减检查直觉，以版本和独立重放维护证据，以备选路线保留思考空间。
